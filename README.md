# Octalve Vote — TypeScript Next.js platform

**Status:** Batch 2 review. Built with **Next.js 16.4.1**, React 19.2.9, strict TypeScript/TSX, Tailwind CSS 4 and PostgreSQL/Prisma 7. The original GoVotin user interface is the migration reference.

## GitHub review branches

- `review/octalve-vote-foundation-2026-10-20`: Batch 1, reviewed public pages and role entry.
- `phase/02-electoral-auth-dashboard`: Batch 2, staff auth foundation and **server-protected** electoral dashboard. Both PRs remain draft; main is production-controlled.

## Setup (public UI only)

```powershell
git clone https://github.com/octalve-core/octalve-vote.git
cd octalve-vote
git switch phase/02-electoral-auth-dashboard
npm install
npm run dev
```

Open `http://localhost:3000`. Public pages and disabled login/registration previews work without a database. No real votes or credentials are accepted by default.

## PostgreSQL dev setup — fresh empty database only

1. Create a **new empty database**, owned by a dedicated local role (do not use the previous `govotin` database).
2. Copy `.env.example` to `.env`; set DATABASE_URL privately and AUTH_THROTTLE_SECRET to a randomly generated 32+ character secret. Keep both off GitHub.
3. Review `prisma/migrations/20261020_batch2_initial/migration.sql`. This SQL was generated by Prisma 7.3 from the schema **without connecting to or changing any database**.
4. Only for the fresh dedicated database, run `npm run db:deploy` and `npm run db:generate`.
5. Enable `ENABLE_STAFF_LOGIN=true` and, if deliberately testing onboarding, `ENABLE_ELECTORAL_SIGNUP=true` in **isolated local testing only**. New organizations remain PENDING/UNPAID. Admin sign-in stays blocked until MFA is implemented.

**Critical**: This baseline is **not** a migration strategy for an existing GoVotin database or any election data. Do not run `db push`, `migrate reset` or blindly apply the baseline against persistent data.

## Verification

```powershell
npm run typecheck
npm run lint
npm run build
npx playwright install chromium
npm run test:browser
```

The single public-preview Playwright recording begins at the homepage and navigates via visible UI only. It tests role gates, not completed authenticated elections.

## Key structure

- `app/(public)`: public routes, staff sign-in and registration entry
- `app/(staff)/electoral`: server-authorized electoral pages
- `app/actions/staff-auth.ts`: login, pending signup and logout server actions
- `components/sections/electoral`: original green/emerald dashboard composition
- `lib/auth`: server-only sessions, feature gates and throttling
- `lib/electoral`: tenant-scoped read-only data queries
- `lib/db`, `prisma`: Prisma 7 + PostgreSQL, new empty-DB baseline
- `tests/e2e`: continuous browser-only UI walkthrough

See `docs/BATCH_02.md` for implemented features, verified limitations and next security gates. **Real ballot casting remains disabled.**
